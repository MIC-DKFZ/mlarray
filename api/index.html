    Create an MLArray from an array, or load a ".mla" file.

    The MLArray file format (".mla") is a Blosc2-compressed array with explicit, domain-neutral metadata (spec docs/design/spec.md).

    Parameters:

    A NumPy array, or the path of a ".mla" file to load. None creates an instance without array data.

    		 None
    axes Optional[Sequence[Union[Axis, str, Mapping]]]

    One entry per array axis, in array order: names ("z"), :class:~mlarray.metadata.Axis objects or dicts with name, type (space, time, channel, component, other) and optional labels or sampling. Defaults to axis_0, axis_1, ... of type space.

    		 None
    spaces Optional[Sequence[Union[Space, Mapping]]]

    Coordinate systems with their from-array transform (:class:~mlarray.metadata.Space or dicts). The first space is the default one.

    		 None
    values Optional[Union[Values, Mapping]]

    What the numbers mean (:class:~mlarray.metadata.Values or a dict with kind, unit, labels ...).

    		 None
    profiles Optional[Mapping]

    Domain metadata by profile name, e.g. {"ml": {...}}.

    		 None

    Arbitrary user metadata; never interpreted.

    		 None

    Original metadata of converted files (read-only afterwards).

    		 None

    Convenience geometry, composed into the from-array matrix of space (see :func:mlarray.metadata.space_from_geometry). They follow the array's space axes in array order: spacing[c] and direction[:, c] belong to array axis c; origin is the centre of index (0, ..., 0) in space coordinates.

    comp_blosc2_params classmethod ¶

    comp_blosc2_params(image_size: Tuple[int, ...], patch_size: Tuple[int, ...], spatial_axis_mask: Optional[list[bool]] = None, bytes_per_pixel: int = 4, max_block_nbytes: int = _layout.DEFAULT_MAX_BLOCK_NBYTES, max_chunk_nbytes: int = _layout.DEFAULT_MAX_CHUNK_NBYTES)

    Compute recommended Blosc2 chunk and block sizes from a patch-size hint.

    Uses nnU-Net's layout heuristic, generalized to any number of spatial and non-spatial axes (:func:mlarray.blosc2_layout_strategies.comp_blosc2_params):

    1. Non-spatial axes (channels, time, ...) get chunk and block
   size 1, so reading one channel touches only its own data.
2. Blocks start at the next power of two of the patch size per
   spatial axis and are halved until they fit ``max_block_nbytes``
   (128 KiB).
3. Chunks grow by whole blocks on the least covered spatial axis
   until they reach ``max_chunk_nbytes`` (6 MiB), the image extent,
   or 1.5x the patch size per axis.

    For 2 and 3 spatial axes the layout is identical to nnU-Net's.

    Parameters:

    Name Type Description Default
    image_size Tuple[int, ...]

    Full array shape.

    		 required
    patch_size Tuple[int, ...]

    Patch size over spatial axes only. A 1 keeps that axis at chunk size 1 (e.g. (1, 256, 256) for 2D slices of a 3D image).

    		 required
    spatial_axis_mask Optional[list[bool]]

    Mask indicating for every array axis whether it is spatial. If omitted, all axes are treated as spatial.

    		 None
    bytes_per_pixel int

    Number of bytes per element. Defaults to 4 for float32.

    		 4
    max_block_nbytes int

    Largest block in bytes.

    		 DEFAULT_MAX_BLOCK_NBYTES
    max_chunk_nbytes int

    Largest chunk in bytes.

    		 DEFAULT_MAX_CHUNK_NBYTES

    Returns:

    Type Description

    Tuple[List[int], List[int]]: Recommended chunk size and block size.

    mlarray.mlarray.set_read_ahead ¶

    set_read_ahead(nthreads: int = MLARRAY_DEFAULT_READ_AHEAD) -> int

    Set blosc2's read-ahead for this process (blosc2.set_prefetch).

    With read-ahead, reading a slice of an on-disk array fetches the chunks it needs with nthreads background threads in parallel, instead of one small request after another. For data that is not in the page cache this makes patch reads several times faster, most on network storage (in our benchmark with 12 nnU-Net-style loader processes on network storage, 3D patches took 64-82% less time). For data already in the page cache it can cost a little (up to about 17% per read with a single reader).

    MLArray turns it on with MLARRAY_DEFAULT_READ_AHEAD (4) threads the first time a file is opened, unless this function was called before or the BLOSC_PREFETCH environment variable is set. The setting applies to the whole process, including other blosc2 arrays it reads; each reader thread gets its own read-ahead threads. Call set_read_ahead(0) to turn it off. Without read-ahead support in the installed blosc2 this does nothing.

    Parameters:

    Name Type Description Default
    nthreads int

    Read-ahead threads per slice being read; 0 turns read-ahead off.

    		 MLARRAY_DEFAULT_READ_AHEAD

    Returns:

    Name Type Description
    int int

    The previous number of read-ahead threads (0 if unsupported).

    Layout Module¶

    mlarray.blosc2_layout_strategies.comp_blosc2_params ¶

    comp_blosc2_params(image_size: Sequence[int], patch_size: Sequence[int], spatial_axis_mask: Optional[Sequence[bool]] = None, bytes_per_pixel: int = 4, max_block_nbytes: int = DEFAULT_MAX_BLOCK_NBYTES, max_chunk_nbytes: int = DEFAULT_MAX_CHUNK_NBYTES, max_chunk_to_patch_ratio_per_axis: Optional[float] = DEFAULT_MAX_CHUNK_TO_PATCH_RATIO, grow_singleton_patch_axes: bool = False) -> tuple[list[int], list[int]]

    Chunk and block sizes for patch-wise reading (nnU-Net's heuristic).

    • Non-spatial axes (channels, time, ...) get chunk and block size 1, so reading one channel touches only its own data.
    • Blocks start at the next power of two of the patch per spatial axis and are halved on the axis most over-represented relative to its target extent until they fit max_block_nbytes.
    • Chunks grow by whole blocks on the least covered spatial axis until max_chunk_nbytes, the image extent, or max_chunk_to_patch_ratio_per_axis times the patch per axis.
    • A patch entry of 1 (e.g. (1, 256, 256) for 2D slices of a 3D image) keeps that axis at 1 unless grow_singleton_patch_axes is set.

    For 2 and 3 spatial axes the result equals nnU-Net's comp_blosc2_params (2D images as (1, y, x)); any other number of spatial axes follows the same rules.

    Parameters:

    Name Type Description Default
    image_size Sequence[int]

    Full array shape.

    		 required
    patch_size Sequence[int]

    Patch size over the spatial axes (one entry per spatial axis).

    		 required
    spatial_axis_mask Optional[Sequence[bool]]

    For every array axis whether it is spatial. All axes are spatial if omitted.

    		 None
    bytes_per_pixel int

    Bytes per array element.

    		 4
    max_block_nbytes int

    Largest block in bytes.

    		 DEFAULT_MAX_BLOCK_NBYTES
    max_chunk_nbytes int

    Largest chunk in bytes.

    		 DEFAULT_MAX_CHUNK_NBYTES
    max_chunk_to_patch_ratio_per_axis Optional[float]

    Largest chunk extent per axis relative to the patch, or None for no limit.

    		 DEFAULT_MAX_CHUNK_TO_PATCH_RATIO
    grow_singleton_patch_axes bool

    Let axes with patch size 1 grow in chunks.

    		 False
