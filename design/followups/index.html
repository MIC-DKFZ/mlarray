    Follow-ups after MLArray 1.0¶

    MLArray 1.0 changes the metadata model completely (docs/design/spec.md) and cannot read v0 .mla files. The libraries below still use the v0 API and need their own rework. Do them one at a time, each on a rework branch, with the same working rules as rework-plan.md.

    Release path (CD)¶

    For all of these repos: local push → GitLab remote (codebase.helmholtz.cloud) → automatic sync to the GitHub remote → a GitHub Actions workflow on a v* tag publishes to PyPI.

    package PyPI trusted publisher notes
    mlarray yes released as 1.0.0 from main
    MedVol yes released as 1.0.0 from main (trusted publishing, tests on Python 3.10-3.13 before publishing)
    napari-mlarray yes check the workflow uses trusted publishing
    SlicerMLArray no released through the Slicer extension index, not PyPI (check)
    napari-nifti no publishes with an API token, or set up trusted publishing
